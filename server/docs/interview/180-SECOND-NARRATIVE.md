# 3 分钟项目讲述

> 这是草稿：请改成你自己的话，并确认每一句你都能展开讲五分钟。所有数字的出处、命令和版本见 [CURRENT-TRUTH.md](CURRENT-TRUTH.md)。数字来自本地 7B 模型，讲的时候说清楚这一点，不要说成生产环境或 GPT 级模型的结果。

**（0:00–0:25）它是什么**

这是一个面向合同、政策、论文这类文档的 Agent 系统。用户上传 PDF 后可以提问、做多文档对比，每个关键结论都要能回到页级引用；证据不够时，系统会补检索、请求澄清或者明确拒答，而不是编一个看起来合理的答案。

**（0:25–1:15）Agent 怎么设计**

核心原则是"模型只提议，运行时做决定"。一次请求先由意图规划器在白名单候选里选意图，再由执行规划器在白名单步骤里排顺序；自定义 Skill 阶段用 typed DAG：模型只输出节点、依赖和输入绑定，校验器对整张图要么接受要么拒绝，不会执行半张非法的图。权限、文档范围、预算、审批、重试上限都由运行时决定，不交给模型。

回答生成后有一个有界的自检循环：逐条核对 claim 的引用支持，有缺口就补检索一轮（最多 3 条查询），finalizer 删掉没有证据支持的内容。运行状态在 PostgreSQL，崩溃后只在能证明安全时续跑：有副作用的步骤不自动重放，旧 worker 的状态写被版本号 CAS 挡住。需要 checkpoint 和中断的图由 LangGraph.js 调度；外层计划交给它时低并发每请求 CPU 多 17.6%，超过 10% 的门，留在原生循环。

**（1:15–2:20）用真实模型测出来的三件事**

早期所有评测都用确定性的伪 embedding，数字好看但说明不了效果。换成本地真实模型（nomic-embed-text + qwen2.5:7b）之后，我发现了三件事。

第一，检索。伪 embedding 下 hybrid 比 BM25 差很多，换成真实 embedding 排序反过来，但 48 条用例上不显著。外部标注的 QASPER 821 题上，hybrid 只显著好于单用 BM25（+0.074），和纯稠密没有显著差异。启发式重排没有提升；交叉编码器让证据进上下文 +0.063，显著，但答案 F1 不显著；它要单独的模型服务，所以默认关。

第二，多文档对比功能 100% 拒答。表面看像 7B 模型能力不够，排查后发现是我自己的校验器拒掉了正确答案：逗号分隔的多来源引用解析不了，vendor-a 这种文件名认不成文档名。修完之后端到端检查从 16/18 到 18/18。但现在对比题靠按证据拼的模板通过，7B 自己写的对比答案仍被词法校验拒绝。

第三，规划器。7B 模型下 56% 的规划调用因为格式错误或越界被降级到确定性规划器。我用按请求从白名单生成的 JSON Schema 做约束解码，降级率降到 8%，用例通过率从 47% 到 80%，延迟基本不变。

**（2:20–2:45）可靠性**

我写了一个故障注入评测，模拟 429、503、请求挂起、空响应和主模型宕机。加上带抖动的退避、遵守 Retry-After、可重试的超时和备用模型切换之后，限流下的成功率从 79% 到 100%，主模型宕机从 0 到 100%；代价是限流时 p95 从 2.5 秒涨到 4.7 秒，因为系统真的在按服务端要求等待。

**（2:45–3:00）边界**

默认只读 PDF 文本层，版面解析和按页分流可选，30 篇论文上答案 F1 没有显著差异，OCR 只在一份手工扫描件上走通；校验器默认是词法的，受限的 LLM 评审让合同题回答率从 3/21 到 14/21 且全对，但没用人工标注校准，在 QASPER 上还会回答不可答题，所以默认关闭；外部标注集已接入，但只测过一个 7B 模型。
